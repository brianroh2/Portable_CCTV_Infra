# SiteGuard 시스템 아키텍처 정리

> 작성: 2026-04-24 / 상태: Phase A·B 진행 중

---

## 1. 전체 구성 개요

SiteGuard는 현장 영상 관제 시스템으로, **에지 현장 → 클라우드 → 관리자 단말** 3개 레이어로 구성된다. 현장과 클라우드 사이는 SKT LTE 회선으로 연결되며, 통신사 인바운드 차단 문제를 Tailscale 터널로 우회하는 구조가 핵심이다.

---

## 2. 레이어별 구성

### 레이어 1 — 에지 현장 (현장 박스)

현장에는 3개 기기가 LTE 라우터 하위 로컬 네트워크(192.168.1.x)에 연결된다.

**IP 카메라 (TVT TD-9421S4C)**
- 고정 IP: 192.168.1.153
- RTSP 프로토콜로 영상 스트림 출력
- 카메라 자체 설정에서 Static IP 고정 (DHCP 미사용)

**LTE 라우터**
- SKT 4G LTE 회선 사용 (공인 IP 보유, CGNAT 아님)
- 게이트웨이: 192.168.1.1
- SKT 정책상 외부→내부 인바운드 포트가 차단됨 → 포트 포워딩 사용 불가
- DDNS(siteguard01.ddns.net) 설정 완료

**라즈베리파이 3B** ← 신규 추가 예정
- go2rtc: 카메라 RTSP 스트림 수신 및 변환
- Tailscale: 클라우드 서버로 아웃바운드 터널 연결
- 추후 추가: Baresip(SIP 통화), Frigate(AI 감지)

---

### 연결 구간 — SKT LTE

SKT 일반 LTE 회선은 **아웃바운드(나가는 방향)는 허용**되지만 **인바운드(들어오는 방향)는 차단**된다. 포트 포워딩, DMZ 등 라우터 설정으로는 해결 불가하며, 라즈베리파이에서 클라우드로 먼저 연결을 맺는 **역방향 터널(Tailscale)** 방식으로 우회한다.

---

### 레이어 2 — 클라우드 (Hetzner CX32)

- 사양: 4 vCPU / 8GB RAM / Ubuntu 24.04
- 위치: 싱가포르 / 월 약 13,000원
- Docker Compose로 서비스 운영

**Thingsboard CE**
- 기기 상태 모니터링, 사용자 관리, 알람 관리, 대시보드 UI 제공
- 포트: 8080

**go2rtc**
- 에지 라즈베리파이로부터 영상 스트림을 받아 관리자에게 중계
- 영상 저장 없음 — 라이브 스트리밍 전용
- 포트: 1984

**Asterisk (추후 Phase D)**
- SIP PBX 교환기
- 비상벨 호출, 현장 방송 기능 제공
- 포트: UDP 5060

**커스텀 UI — mobile-cctv-vms (추후 Phase D)**
- React/TypeScript 기반 관제 화면
- Thingsboard API + go2rtc 영상 통합

---

### 레이어 3 — 관리자 단말

**브라우저 관제**
- Thingsboard 대시보드로 기기 상태, 알람 확인
- go2rtc 라이브 영상 확인

**스마트폰 (추후)**
- Linphone 앱으로 SIP 통화 수신
- 비상벨 알림 수신

**개발 PC**
- VS Code Remote SSH로 클라우드 서버 직접 편집
- Claude Code로 AI 개발 보조

## 3. 핵심 설계 원칙

| 원칙 | 내용 |
|------|------|
| 영상 저장 | 에지 전용 (SD카드/HDD). 클라우드는 라이브 중계만 |
| 인바운드 우회 | Tailscale 아웃바운드 터널. 포트 포워딩 미사용 |
| 스택 최소화 | Tailscale, Docker Compose, GitHub, VS Code SSH |
| 단계적 확장 | 핵심 기능 먼저, SIP·커스텀 UI는 후속 단계 |

---

## 4. 단계별 구현 계획

**Phase A·B (현재 진행 중)**
라즈베리파이 OS 설치 → Tailscale 연결 → go2rtc 설치 → 카메라 RTSP 스트리밍 확인

**Phase C**
Thingsboard 텔레메트리 연동 → 클라우드 go2rtc 영상 중계 → 기기 상태 대시보드 구성

**Phase D (추후)**
Asterisk SIP 구축 → 비상벨·현장 방송 → 커스텀 관제 UI 개발

---

## 5. 현재 확인된 사항

- TVT 카메라 내부 접근(192.168.1.153:554) 정상 확인
- DDNS(siteguard01.ddns.net → 42.18.98.130) 연결 정상
- SKT 인바운드 차단으로 외부 직접 접근 불가 확인 → Tailscale 터널 방식으로 전환 확정
- Hetzner CX32 서버 운영 중
- 라즈베리파이 3B 추가 투입 예정
